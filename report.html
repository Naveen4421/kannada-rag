01 · Overview

What this system does

The project is a Retrieval-Augmented Generation (RAG) system for searching and answering questions over a collection of Kannada-language books. A user asks a question in Kannada; the system retrieves the most relevant passages from the indexed books and passes them to a large language model, which answers using only that retrieved text and cites its source (book, author, page, chunk).

The system is now split into two clearly separated pipelines, each with its own Streamlit UI page: a dataset pipeline that turns a .docx/.txt file into indexed vectors (title/author read automatically from the book's own opening pages), and a query pipeline that routes each question by complexity, retrieves via hybrid dense+keyword search, reranks with a real cross-encoder, and either streams a fast answer or runs a bounded self-critique loop.

Currently indexed: 7 sources / 1,964 chunks — 5 historical/biographical .docx books, 1 science-magazine .txt OCR dump, and 1 small test file.

02 · Technology stack

What it's built from

Everything runs locally in a single Python 3.12 virtual environment, with Qdrant running as a separate Docker container — no other external service except the OpenRouter API call at generation time.

03 · Architecture & workflow

Two pipelines, one shared index

The dataset pipeline fills a shared hybrid Qdrant collection offline (or on-demand via the Ingest page). The query pipeline queries that same collection at ask-time. The router is the fork point: simple questions take the fast streaming path; open-ended questions get a bounded self-critique loop that can broaden retrieval and rewrite the query.

05 · Two-pipeline UI

One process, two pages

A Streamlit multipage app — one running process (one shared, cached embedding model in memory, not duplicated across servers), two distinct pages in the sidebar.

📥 Ingest Data

File uploader (.docx/.txt only), no manual fields. Runs the full dataset pipeline, shows a success summary with the auto-extracted title/author, or a clear error. Lists currently indexed books.

🔎 Ask Questions

Book filter, question box. Shows a route badge (simple/complex, cache hit, agent iteration count), streams the answer live on the fast path, shows cited sources in expandable panels.

08 · Fixes made this pass

Real bugs found and fixed

Worth recording since they're not obvious from the code alone:

  • Silent streaming failures — the query dispatcher hardcoded "error": None on its streaming return, before the stream was consumed. An LLM failure mid-stream was logged to file but never shown in the UI. Fixed with a shared mutable error holder the UI checks after consuming the stream.
  • Unhandled crashes on retrieval failures — only the final LLM call was error-guarded; a GPU OOM during embedding/search/rerank crashed the dispatcher entirely. Every stage is now guarded and degrades to a clean error message.
  • 402s despite having balance — requests with no explicit max_tokens get OpenRouter's default ceiling (16k+), reserving more budget than a small balance can cover. Fixed by capping max_tokens=1024 on every call.
  • .txt ingestion collapsing to one giant chunk — the loader only split on blank lines; a real OCR export with zero blank lines (711 single-newline lines) became one unsplittable ~390KB "paragraph." Fixed with a one-paragraph-per-line fallback.
  • Streamed Kannada rendering as mojibake — requests' auto encoding detection failed on the SSE stream (UTF-8 decoded as Latin-1). Fixed by decoding each line explicitly as UTF-8.
09 · Limitations & roadmap

What's deliberately not done yet

  • PDF ingestion still deferred — ingestion/pdf_parser.py exists but produces a schema the chunker can't consume.
  • RAGAS LLM-judged metrics need a credits top-up to get a real reading — currently only the free ID-based metrics are valid.
  • GPU is shared with other processes on this host — reranking/embedding can transiently OOM under contention; now degrades gracefully instead of crashing.
  • Four of the original five books still carry filename-default metadata — the new auto-extraction will fix this on the next re-ingest once credits are available.
  • Docker path exists but isn't the primary day-to-day run path — local .venv + Docker-hosted Qdrant is what's actually being used and tested.
